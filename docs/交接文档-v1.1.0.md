## 三、关键约定与坑（**最重要的一节**）

### 3.1 版本门禁（硬约束）

`sw.js` 的 `konllen-site-vX.Y.Z` 是**单一事实源**。任何**可见**改动（**包括只改 CSS / JS / 甚至只调 HTML 元素顺序**）都必须：

1. bump `sw.js` 的 CACHE；
2. 同步 bump 全部 HTML 的 `?v=` 引用。

```bash
python tools/bump_version.py      # 不传参 = 读 sw.js 自动 patch +1；也可 --from/--to 显式指定
python tools/check_version.py     # 门禁：316 处 ?v= / 30 个 HTML 必须全部一致
```

`check_version.py` 已在 `.github/workflows/ci.yml` 里锁死，push 到 main 必跑。

### 3.2 改文案必须改三处（v1.8.7 / v1.8.8 的核心发现）

| # | 位置 | 谁看得到 |
|---|---|---|
| ① | `js/i18n.js` 的 zh **与** en 真值 | 正常访客（运行时覆盖） |
| ② | HTML 里同 key 元素的**静态 fallback** 文本 | **爬虫**、禁用 JS 的访客、首屏闪动 |
| ③ | `meta[name=description]` / `og:*` / `title` | **搜索引擎结果页、社交分享卡片** ← 最易漏 |

②③ 是盲区：`i18n.js` 用 `textContent` 覆盖，所以**用户看到的永远是对的，错的藏在别人眼里**。

```bash
python tools/check_i18n.py        # 报告 ①② 的漂移（358 key / 722 个 data-i18n 元素）
python tools/check_i18n.py --fix  # 以 i18n.js 为准回写 HTML
```
③ 目前**没有自动化**，改口径时要手动 grep `meta`/`og`/`title`。

### 3.3 多行 HTML 开标签必须带 `>`

`<div class="journey-card card p-card p-glow"` 换行写属性时**漏掉 `>`** → 浏览器把紧随的 `<span …>` 当作属性吞掉 → **子元素全部消失**（页面"看起来渲染了"，但内容没了）。v1.8.6 就栽在这里。

**验证纪律**：不能只看整页出图，必须**断言目标元素的子节点存在**（实测修好后为 `[SPAN.journey-date, SPAN.journey-tag, H3, P]`）。

### 3.4 CSS 同特异性看加载顺序

`patterns.css` 在 `style.css` **之后**加载，`.p-card{display:flex;flex-direction:column}` 与 `.journey-card{display:inline-block}` **同特异性 (0,1,0)** 却更靠后 → 卡片被变成 flex 列容器，**子元素整体块级化**（标签药丸被拉成全卡宽空横条，实测宽度 = 286px）。

修法：提高特异性 `.journey .journey-card { display:inline-block; }`（(0,2,0)）。**症状隐蔽 —— 是"子元素被布局改变"，不是"样式没生效"。**

### 3.5 可上线文件名一律 ASCII 且 < 200 字节

中文按 3 字节/字，长中文 slug 极易越过 ext4 的 **255 字节**上限 → GitHub Actions `actions/checkout` 报 `File name too long` → CI 与 Pages `build` 双双失败、`deploy` 被 skip → **站点静默冻结在旧版本**（v1.8.5 就是被这个卡住，站点曾停在 v1.8.2）。

**推论：API 推送成功 ≠ 站点上线。** 推送后必须核对 `actions/runs`。

### 3.6 其他踩过的坑（速查）

| 坑 | 表现 | 正解 |
|---|---|---|
| **cp936 写文件** | v1.8.3 bump 把 HTML 中文写坏 | 写文件一律**字节级 IO / UTF-8**（v1.8.4 重做） |
| **git 引号污染路径** | 八进制转义 `\344\272\244…` 被当字面路径写进 tree | 八进制转义**整段聚合成字节再整体 UTF-8 解码**；用 `os.walk` 取干净名 |
| **`git ls-files` / `git status` 文本当路径** | 本机输出 GBK 文件名，`isfile` 误判 11 个文件缺失 | 一律用 `-z` 或 `os.walk` |
| **路径过滤失效** | `startswith("methods/")` 匹配不上被污染的路径 | 同上一行 |
| **`--stdin-paths` 少 `--no-filters`** | 凭空多出 21 个假改动 | `git hash-object --stdin-paths --no-filters`，且前提 `core.autocrlf=false` |
| **`core.autocrlf=true`** | `reset --hard` 把 LF 检出成 CRLF，`git status` 假装干净 → 盲推把几十个文件行尾改上线 | `git config core.autocrlf false`（仓库级） |
| **索引 stat 缓存「幽灵 M」** | `git status` 报改动但 `git diff` 全空 | `git add -u` 重算索引 |
| **Windows 子进程 stdin 被翻 CRLF** | `subprocess.run(text=True)` 把 `\n`→`\r\n`，`git check-ignore --stdin` 逐行匹配全落空 | **stdin 一律传 bytes** |
| **大响应截断** | `api.github.com` 对 >~700KB 响应间歇 `IncompleteRead`；`raw.githubusercontent.com` 被完全阻断 | blob 优先用**本地同名文件回填**（sha 相等 ⇔ 逐字节相同，零网络） |
| **一次推多条提交** | 只有最后一条生效 | 推前 `git commit --amend` 压成一条 |

## 六、Git 推送与本地对齐（「影子仓库」教训）

**问题**：长期走 API 推送绕行，而 **API 推送不回写本地 git** → 本地历史与远端分叉。本次实测分叉点 **v1.7.8**：共同 70 提交 / 本地独有 3 / 远端独有 16。本地独有的 3 个提交与远端**信息雷同但 SHA 完全不同**（API 重建的同名提交；**同名 ≠ 同一个**）。

**危害**：`git log` 看不到真实版本、`git pull` 必冲突、**本地不能当回滚点**。

**判据**：判断是否分叉必须**比 SHA**（远端提交列表 ∩ 本地 `rev-list`），不能看 `git log` 像不像。

**正解**：
```bash
python tools/sync_local.py            # --check 只查 / --force 丢弃未提交改动 / --no-backup 不打包备份
```
它会取远端分支头 → 按需在本地重建同 SHA 的 commit/tree/blob 对象 → `reset --hard` → 复核 HEAD / tree / 提交数。

### ⚠️ 铁律：凡走 API 推送，推后**必须**跑 `sync_local.py`

唯一豁免：推送前本地与远端已严格对齐（此时 API commit 以本地提交为父，不产生分叉）。

### ⚠️ 闸门 = 内容一致性，不是 tree SHA 相等

拉回构建的 tree（递归 GET），逐条比对 `(path, blob_sha)` 集合 —— 缺失 / 多余 / 不一致 均为 0 才算过。

**绝对不要用 `NEW_TREE == HEAD^{tree}` 逐位比** —— Trees API 把前导点路径（`.github`、`.gitignore`）"排后"，而 git 按字节序把 `.` 排最前，同一组文件两边 tree SHA **必然不等**。（v1.0.0 文档在这里写错了，见 §11。）

**当前状态**：本地 HEAD `e24bbd8` == 远端，tree `c3cd7fe1` 双向一致，90 提交，`git status` 干净，`core.autocrlf=false`。

## 八、出图规范（截图验证 / 交付）

### 8.1 「内容消失」的两个假象

1. **滚动入场动画未触发** —— `js/main.js` 给 `.card` / `.blog-item` / `.section-title` / `.hero-card` 加 `.reveal`（隐藏），滚入视口才加 `.visible`。而 `fullPage` 截图**不会真的滚动页面** → 观察器永不触发 → **首屏以下全部隐形**（整页图看起来"只剩导航和页脚"，极易误判成 CSS/字体故障）。
   **正解**：截图前
   ```js
   document.querySelectorAll('.reveal').forEach(el => {
     el.classList.add('visible'); el.classList.remove('reveal');
   });
   ```
   再渐进滚到底回顶（顺带触发图片懒加载）。
   > 同类问题已内建进技能 `report-to-png`（v1.6.0 起脚本自动兜底）。
2. **元素截图裁掉最后一张卡** —— `elementHandle.screenshot()` 也会因末卡仍在 `.reveal` 而看不到。

### 8.2 其他截图纪律

- **`clip` 与 `fullPage` 互斥** → 取局部用 `elementHandle.screenshot()`。
- 截图前隐藏 `position:fixed/sticky` 的吸顶栏，否则盖住元素顶部。
- 参数：viewport 宽 1280、`deviceScaleFactor: 1.5`、`fullPage: true`。
- `fullPage` 下 `position:fixed` 元素**只在页面顶部画一次**（不会每屏重复）。
