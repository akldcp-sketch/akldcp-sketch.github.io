汇率敞口别只看波动率：多币种结算的账期闸门与锁汇排队

2026-11-26 · 商业操盘

多币种结算的团队把汇率当背景噪声，月底看一眼汇兑损益，然后继续。口径错了：汇率对利润的冲击不看波动率大小，看波动率乘上账期，再乘上毛利对汇率的弹性，而弹性就是毛利率的倒数。六类币种站点、年回款 2,840 万元的算例：单窗口一个标准差的汇率波动，GBP 站点吃掉 6.97% 毛利，等于该站点净利率 6.8% 的 102.4%——一个 σ 就把净利打到零以下；账期闸门 T* = 365 × (θ·G ÷ σ)² 划出六类里五类已超标，其中三类靠缩短账期根本救不回来；锁汇不是全锁，按 R = σ√(2/π) ÷ h 排队，先做前四类只需 207,900 元成本，换来 732,965 元净收益，占全量净收益 1,062,455 元的 69.0%。按回款额排队的话，第一顺位恰恰是效费比最差的 USD。

一、2,840 万回款里的 5.00%：汇率不是背景噪声

六类币种站点的年回款合计 2,840 万元，年化汇率波动率从 4.6%（USD）到 9.8%（JPY）。按半正态期望值算，一年不利方向的汇兑损失是 1,420,155 元，占回款的 5.00%。这笔钱不进损益表的「汇兑损益」一行——它分两年、六个币种、上百笔结算陆续落进毛利，等财务把它归集出来，SKU 定价和广告预算已经按错的毛利率调过三轮。

更麻烦的是口径。多数团队盯波动率：JPY 9.8% 高、USD 4.6% 低，结论变成「日元站风险大」。波动率只是三个变量之一。真正决定敞口的是这笔钱暴露多久——账期。账期 21 天的 CAD 站点，σ 只有 5.7%，单窗口冲击 6.19% 毛利，反而高于 σ 6.3% 但账期 14 天的 EUR 的 5.82%。波动率的解释力，不如「波动率除以账期平方根」。

sigma_T = sigma * sqrt(T / 365)
impact  = sigma_T / G          # 1-sigma hit to gross profit
E       = 1 / G                # elasticity of gross profit to FX
T_gate  = 365 * (theta * G / sigma) ** 2
R       = sigma * sqrt(2 / pi) / h
P_new   = P / (1 - x)          # price that restores local-currency revenue

式中：σ 为年化汇率波动率，T 为平台回款账期（天），G 为毛利率，θ 为可容忍的汇兑冲击上限（取净利率的一半），h 为远期锁汇年化点差，x 为汇率跌幅。率一律用小数；混用百分数是最常见的错。

二、账期是敞口的放大器：翻倍只涨 41%，但足够改结论

汇率近似随机游走，T 天窗口的波动率按时间平方根缩放。账期从 T+14 延到 T+28，敞口涨 1.414 倍，不是 2 倍；从 T+14 延到 T+60，涨 2.07 倍。这条平方根律有个直接用途：给「提前回款」定价。

USD 站点账期 14 天时单窗口 1σ 冲击 3.75% 毛利，延到 28 天是 5.31%。若平台提供的加速回款收 1.2% 手续费，账面上 5.31 − 3.75 = 1.56 个百分点比 1.2% 划算；但 1.56 个百分点是 1σ 情形，取期望要打 0.798 折，实际 1.24 个百分点，与手续费几乎持平，方案恰在临界线。这类账把平方根写出来才算得清，凭「早回款总是好的」下判断，等于用 1.2% 的确定成本换 1.24% 的期望收益，还是带方差的收益。

三、单窗口一个 σ 就吃掉一半净利：弹性是毛利率的倒数

毛利额对汇率的绝对冲击恒等于回款额乘汇率变动幅度，与毛利率无关——这是第一层容易算错的地方。相对冲击要除毛利率：毛利率越低，同一笔汇兑损失占毛利的比例越高。弹性 E = 1/G，USD 的 24.0% 毛利对应 4.17 倍，GBP 的 19.4% 对应 5.15 倍。低毛利不是「薄利多销」，是「薄利先碎」。

换算到净利口径才是能拍桌子的数。USD 单窗口 1σ 吃掉 3.75% 毛利，占净利率 8.0% 的 46.9%——一个标准差波动，半个净利没了。GBP 是 6.97% 对 6.8%，102.4%：账期 14 天、毛利率 19.4% 的站点，汇率不需要「大幅波动」，正常波动就足以让一个季度的净利归零。这句话该写进周会材料，而不是等年底汇兑损益出来再复盘。

四、账期闸门：五类超标，三类靠谈账期救不回来

闸门 T* = 365 × (θ·G ÷ σ)²，θ 取净利率的一半，含义是「汇兑冲击不许吃掉超过一半净利」。六类里只有 USD 过关：闸门 15.9 天，现行 T+14。其余五类全超标，最紧的 GBP 是 3.3 天，AUD 4.5 天，EUR 5.7 天，JPY 7.1 天，CAD 9.0 天。

闸门的用处不是催人去谈账期，而是指出哪条路根本走不通。GBP 要把账期压进 3.3 天，现实里没有平台做得到，这条路径直接判死，只剩锁汇或调价；EUR 5.7 天、JPY 7.1 天、AUD 4.5 天同样做不到。六类里五类在「缩短账期」这一栏是空白，闸门真正的输出是：汇率风险必须从运营侧推到财务侧，别再指望靠谈账期解决。这是判断，不是建议。

五、别按回款额排队：锁汇效费比 R 决定先做谁

到这一步，团队的标准动作是「全部锁掉」。全锁确实不亏：年期望不利损失 1,420,155 元，锁汇成本 357,700 元，净 1,062,455 元，占回款 3.74%。但额度、保证金、财务人力都有约束时，全锁不是唯一选项，也不是最优启动顺序。

效费比 R = σ√(2/π) ÷ h 给出排序。JPY 以 8.23 排第一：波动率最高 9.8%，点差最便宜 0.95%，日元利差结构使然。USD 以 3.19 排最后：回款额最大，但 1.15% 的点差相对 4.6% 的波动率不便宜。按 R 做前四位——JPY、AUD、GBP、EUR——成本 207,900 元，净收益 732,965 元，占全量净收益的 69.0%，留存敞口 479,289 元。用 58.1% 的成本拿到 69.0% 的收益，后两位随时补。按回款额排队的第一顺位是 USD，而它恰好是效费比最差的一档。

六、提价补偿不是加 x%：等价换算是 x ÷ (1 − x)

用提价抵消汇率跌幅，最常见的错是按跌幅原样加价。本币收入要回到原值，售价得按 P′ = P ÷ (1 − x) 提，因为提价本身也在这笔折算里。跌 5% 要提 5.26%，跌 8% 要提 8.70%，跌 10% 要提 11.11%。跌幅越大两者偏离越明显，10 个百分点时差 1.11 个点，够一个 SKU 的促销预算。

另一半是止损线：净利归零的汇率跌幅，恰好等于净利率。USD 净利率 8.0%，汇率跌 8.0% 就白干；GBP 净利率 6.8%，跌 6.8% 归零；AUD 7.5% 对 7.5%。这条线比「波动率多少算高」有用，因为它对应一个可监控的汇率点位：把开票日即期汇率与预算汇率一比，触及跌幅就触发预定动作，不用开会讨论。

七、可复现脚本：零依赖，跑一遍复现全部结论

脚本只用 math，六类币种的参数硬编码在表里，跑出来是上面三张表的全部数字。把自己的账期、点差、毛利率换进去，就能得到自己站点的闸门与排队顺序。

# fx_settlement_gate.py - settlement-lag gate and hedge queue for multi-currency books
import math

K = math.sqrt(2 / math.pi)   # half-normal expectation coefficient, 0.7979

# currency, annual collections (CNY), gross margin, opex ratio,
# settlement lag (days), annualised volatility, annualised hedge spread
BOOK = [
    ("USD", 11_200_000, 0.240, 0.160, 14, 0.046, 0.0115),
    ("EUR",  6_200_000, 0.212, 0.138, 14, 0.063, 0.0135),
    ("GBP",  3_800_000, 0.194, 0.126, 14, 0.069, 0.0145),
    ("JPY",  3_400_000, 0.271, 0.170, 21, 0.098, 0.0095),
    ("AUD",  2_300_000, 0.249, 0.174, 14, 0.084, 0.0160),
    ("CAD",  1_500_000, 0.221, 0.140, 21, 0.057, 0.0140),
]

def window_impact(sigma, days, gross):
    """1-sigma FX impact inside one settlement window, as a share of gross profit."""
    return sigma * math.sqrt(days / 365) / gross

def lag_gate(gross, net, sigma, tol=0.5):
    """Longest settlement lag for which a 1-sigma window eats at most tol of net margin."""
    theta = net * tol
    return 365 * (theta * gross / sigma) ** 2

def hedge_ratio(sigma, spread):
    """Expected adverse loss per unit of hedge cost (annualised, half-normal)."""
    return sigma * K / spread

def reprice(x):
    """Price increase that restores local-currency revenue after a decline x."""
    return x / (1 - x)

print(f"{'ccy':4}{'1sig/gross':>11}{'vs net':>8}{'T*':>7}{'over':>6}{'R':>6}")
rows = []
for ccy, rev, gross, opex, days, sigma, spread in BOOK:
    net = gross - opex
    imp = window_impact(sigma, days, gross)
    gate = lag_gate(gross, net, sigma)
    r = hedge_ratio(sigma, spread)
    rows.append((ccy, rev, sigma, spread, imp, net, gate, r))
    print(f"{ccy:4}{imp*100:>10.2f}%{imp/net*100:>7.1f}%{gate:>7.1f}{'Y' if days > gate else '-':>6}{r:>6.2f}")

total = sum(r[1] for r in rows)
loss = sum(r[1] * r[2] * K for r in rows)
cost = sum(r[1] * r[3] for r in rows)
print(f"\ncollections {total:,}  expected loss {loss:,.0f} ({loss/total:.2%})")
print(f"hedge all   cost {cost:,.0f} ({cost/total:.2%})  net {loss-cost:,.0f} ({(loss-cost)/total:.2%})")

print("\nqueue by R (highest first):")
cum = 0.0
for ccy, rev, sigma, spread, imp, net, gate, r in sorted(rows, key=lambda x: -x[7]):
    cum += rev * sigma * K - rev * spread
    print(f"  {ccy}  R={r:5.2f}  loss {rev*sigma*K:>9,.0f}  cost {rev*spread:>8,.0f}  cum net {cum:>9,.0f}")

print("\nreprice after a decline:")
for x in (0.02, 0.05, 0.08, 0.10):
    print(f"  decline {x:.0%} -> raise {reprice(x):.2%}")

八、落地口径：把 T* 和 R 写进结算表与锁汇日历

  1. 结算表加两列：σ（年化）与 T（账期）。没有这两列，汇率讨论永远停在「最近美元涨了」。
  2. 每月算一次闸门 T*，超标的站点在锁汇日历上标记。闸门值越小优先级越高，与回款额无关。
  3. 锁汇按 R 排队，不按金额排队。USD 这类效费比最低的币种放最后，不是它不重要，是它的点差贵，早锁等于多付。
  4. 提价补偿一律用 x ÷ (1 − x)，不用 x。1 个百分点的差异在低毛利 SKU 上就是一个促销位。
  5. 把净利率写进汇率监控表当止损线：跌幅触及净利率，当天触发调价或锁汇，不等月末汇兑损益。月末的数字是结论，不是信号。
