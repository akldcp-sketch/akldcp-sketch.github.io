满减不等于直降：等效折扣率与毛利稀释底线的测算口径

2026-11-06 · 商业操盘 · AI 技能包

满 100 减 25 的标称折扣是 25%，实际让掉的只有 18.9%；另一家店直降 12%，一分不少。这不是文字游戏——它决定你这个月是花 185.8 万元买到 2000.2 万元 GMV，还是按 260 万元做预算、只花出去 185.8 万元，然后在季末急急忙忙把钱补成一堆无效促销。本文用 6 家店、24 条订单档位、月 GMV 2000.2 万元的算例，把等效折扣率、毛利稀释底线与凑单的边际账拆成可执行口径，附零依赖脚本，输出与表格逐格对得上。

一、标称折扣率不能用来做预算：三个误判

第一个误判是把“满 A 减 B”里的 B/A 当折扣率。它只在一种情况下成立：每笔订单金额恰好等于 A。真实订单分布里有两类反例——未达门槛的订单优惠为零，把整体等效折扣率往下拉；超出门槛的订单，溢出部分不享受额外优惠，同样稀释等效率。S1 店“满 1200 减 120”标称 10.0%，实际等效只有 6.54%，差 3.46 个百分点，折到 520.1 万元 GMV 上是 18.0 万元预算虚高。

第二个误判是把等效折扣率当让利幅度。折扣率不是成本，可控边际贡献（CM1）才是成本。同一个 18.87% 的等效折扣，把 S5 的 CM1 率从 24.00% 压到 9.34%，掉 14.65 个百分点；放到 S1 身上只从 47.00% 压到 38.16%，掉 8.84 个百分点。成本率越高，同样的折扣打得越深——因为折扣抬高了“成本 ÷ 实收”这个比值。

第三个误判是把满减和直降放在同一把尺子上比。满减有稀释、也有凑单杠杆；直降没有稀释、也没有杠杆。S4 店直降 12%，等效就是 12.00%，一分不差——这既是“直降看起来更贵”的数学原因，也是它在低毛利店里反而更安全的理由。

二、等效折扣率的算法：按订单档位加权

定义很直白：等效折扣率 = 实际让出的优惠总额 ÷ 优惠前 GMV。满减按“每满 A 减 B”判定叠加档数，直降按比例计提。关键是分子必须来自订单金额分布，不能用标称值反推。

eq = Σ(订单数 × 单笔优惠) / Σ(订单数 × 单笔金额)

满减：单笔优惠 = floor(单笔金额 / 门槛) × 减免额
直降：单笔优惠 = 单笔金额 × 直降比例

两个细节决定结论。第一是叠加：S1 的 2680 元订单按“每满 1200 减 120”付两档、减 240 元，等效 8.96%，低于单档口径的 10.0%。第二是门槛达成：S1 有 18% 的订单落在 980 元档，一笔都没减。两个效应叠加，把 10.0% 压成 6.54%。所以等效折扣率不是运营拍出来的，是订单金额分布算出来的。

口径上还有一条必须钉死：分母是“优惠前 GMV”，不是实收。不少团队用实收做分母，等效折扣率会被系统性高估——同一个 S5 会从 18.87% 变成 23.26%，判定立刻失真，处置动作也会跟着做错。

四、毛利稀释底线：把折扣率上限反解出来

底线不该拍成“折扣不超过 X%”，而应按成本结构反解。CM1 率（对实收）= (1 − 变动费用率) − 成本率 ÷ (1 − 等效折扣率)，注意分母是实收不是 GMV，成本率越高，折扣对它的放大越明显。给定期望的 CM1 率 m（本文取 12%），就能解出该店能承受的等效折扣率上限。

eq_max = 1 − 成本率 / (1 − 变动费用率 − m)

CM1 率（对实收）= (1 − 变动费用率) − 成本率 / (1 − 等效折扣率)

这个式子把责任分清了：成本率高的店，上限自动收紧。S5 成本率 0.63、变动费用率 0.13，在 12% 的 CM1 底线口径下上限只有 16.00%；S1 成本率 0.38、变动费用率 0.15，上限 47.95%。同一个 18.87% 的等效折扣，放在 S1 是毛毛雨，放在 S5 就是击穿。

五、凑单的边际账：低毛利店凑单等于送钱

满减真正的作用是抬客单，但抬客单不等于赚。以 S5 的“满 100 减 25”为例：一笔 88 元的订单不享优惠，实收 88.00 元，成本 55.44 元，变动费用 11.44 元，CM1 = 21.12 元；顾客为凑门槛加到 105 元，减 25 元后实收 80.00 元，成本 66.15 元，变动费用 10.40 元，CM1 = 3.45 元。GMV 涨了 19.3%，CM1 少了 17.67 元。

同样的动作放到 S1 就成立：980 元订单凑到 1450 元，实收从 980.00 涨到 1330.00，成本从 372.40 涨到 551.00，变动费用从 147.00 涨到 199.50，CM1 从 460.60 涨到 579.50，增量 +118.90 元。差别不在门槛设计，在成本率——凑单加的是“增量实收 × (1 − 变动费用率) − 增量成本”，成本率高的店，这个式子天然为负。

六、四种该立刻改掉的促销结构

第一种，用标称折扣率做预算。六店逐个比对：S2 高估 19.2 万元、S1 高估 18.0 万元、S5 高估 17.8 万元、S3 高估 12.3 万元、S6 高估 11.2 万元，合计 78.5 万元。按这个数字申请预算，要么花不出去，要么在季末被“冲促销”乱花掉——两种结局都难看，且都会在下个月的报表上追责到运营头上。

第二种，用统一折扣率管全店。同一条 12% 的折扣线，S1 还有 41.4 个点缓冲，S5 已经翻负 2.87 个点。折扣权限必须按店给，按职级给等于让高毛利店替低毛利店背锅。

第三种，拿 GMV 当促销成功指标。S5 月 GMV 290.0 万元，在矩阵里排第四，CM1 只有 22.0 万元——它用 14.5% 的 GMV 只贡献了 3.7% 的 CM1。促销考核只看 GMV，等于奖励把钱花得最狠的那家店。

第四种，不做结构替换。把 S5 从“满 100 减 25”换成直降 12%：实收 255.2 万元（+19.9 万元），CM1 39.3 万元（15.4%），比现状多 17.3 万元/月，年化 207.8 万元。代价是客单价会掉、凑单效应消失；但只要该店客单价本来就低、凑单增量为负，这个代价就是假代价。

七、脚本与月度落地口径

脚本只用标准库。输入列固定：store、tier、orders、avg_amount、promo_type、threshold、reduction、discount_rate、cost_rate、vfee_rate。promo_type 取 MB（满减）或 DR（直降），直降填写 discount_rate，满减填写 threshold 与 reduction。

# -*- coding: utf-8 -*-
"""满减 / 直降 等效折扣率与毛利稀释底线测算（零依赖）"""
import csv
import sys

TARGET_CM = 0.12  # 目标 CM1 率（对实收），按季度经营目标调整


def load(path):
    with open(path, encoding="utf-8") as f:
        return [dict(r) for r in csv.DictReader(f)]


def tier_metrics(r):
    gmv = int(r["orders"]) * float(r["avg_amount"])
    if r["promo_type"] == "MB":
        th, red = float(r["threshold"]), float(r["reduction"])
        units = int(float(r["avg_amount"]) // th)        # 每满可叠加
        disc = units * red * int(r["orders"])
        nominal = red / th
    else:                                               # DR 直降
        nominal = float(r["discount_rate"])
        disc = gmv * nominal
    return {"store": r["store"], "orders": int(r["orders"]), "gmv": gmv,
            "disc": disc, "eq": disc / gmv if gmv else 0.0, "nominal": nominal,
            "cost_rate": float(r["cost_rate"]), "vfee_rate": float(r["vfee_rate"])}


def store_metrics(rows):
    gmv = sum(r["gmv"] for r in rows)
    disc = sum(r["disc"] for r in rows)
    nominal = sum(r["nominal"] * r["gmv"] for r in rows) / gmv   # 按 GMV 加权
    cost_rate, vfee_rate = rows[0]["cost_rate"], rows[0]["vfee_rate"]
    eq = disc / gmv
    net = gmv - disc
    cm1 = net - gmv * cost_rate - net * vfee_rate
    eq_max = 1 - cost_rate / (1 - vfee_rate - TARGET_CM)         # 反解折扣上限
    return {"store": rows[0]["store"], "gmv": gmv, "disc": disc, "eq": eq,
            "nominal": nominal, "net": net, "cost": gmv * cost_rate,
            "cm1": cm1, "cm1_rate": cm1 / net, "eq_max": eq_max,
            "breach": eq > eq_max}


def report(tiers):
    groups = {}
    for t in tiers:
        groups.setdefault(t["store"], []).append(t)
    out = [store_metrics(v) for _, v in sorted(groups.items())]
    head = "%-4s %8s %7s %7s %7s %8s %7s %7s  %s"
    print(head % ("店", "GMV万", "标称", "等效", "优惠万", "实收万", "CM1率", "上限", "判定"))
    for r in out:
        print(head % (r["store"], "%.1f" % (r["gmv"] / 1e4), "%.1f%%" % (r["nominal"] * 100),
                      "%.1f%%" % (r["eq"] * 100), "%.1f" % (r["disc"] / 1e4),
                      "%.1f" % (r["net"] / 1e4), "%.1f%%" % (r["cm1_rate"] * 100),
                      "%.1f%%" % (r["eq_max"] * 100), "击穿" if r["breach"] else "安全"))
    g = sum(r["gmv"] for r in out); d = sum(r["disc"] for r in out)
    n = sum(r["net"] for r in out); c = sum(r["cost"] for r in out)
    m = sum(r["cm1"] for r in out)
    print("合计 GMV %.1f 万 优惠 %.1f 万 等效 %.2f%% 实收 %.1f 万 CM1 %.1f 万（%.2f%%）"
          % (g / 1e4, d / 1e4, d / g * 100, n / 1e4, m / 1e4, m / n * 100))
    return out


if __name__ == "__main__":
    path = sys.argv[1] if len(sys.argv) > 1 else "promo.csv"
    report([tier_metrics(r) for r in load(path)])

跑法：python3 promo_eq.py promo.csv。用本文 24 行数据跑，输出与表 1、表 2 逐格对得上：合计 GMV 2000.2 万元、优惠 185.8 万元、等效 9.29%、实收 1814.4 万元、成本 954.9 万元、CM1 602.3 万元（33.20%），S5 唯一击穿。换数据源只要列名不变，脚本一个字不用改。

月度节奏就三件事：每月 2 日拉上月订单金额分布（店铺 × 金额档），3 日出等效折扣率与上限对照表，5 日处置击穿店——只有三个选项：改结构（满减换直降）、降档（门槛上调）、收窄适用（限品类或限会员），不接受“下月再看”。把公式、判定规则、输出格式写进技能包的 front matter，AI 每月只做取数、算率、出清单；人只做两件：签处置单、跟平台谈资源置换。

八、结语：促销是对现金的支取

《孙子兵法·计篇》讲“夫未战而庙算胜者，得算多也”。促销既是给顾客的承诺，也是一次对现金的支取；庙算不细，月底账上就只剩一句“我们做了活动”。2000.2 万元的 GMV 里，让出去的 185.8 万元是能一笔一笔算出来的——算不清的那部分，才是真正贵的那部分。
