用 AI 技能矩阵落地个人博客：web-design-skill-matrix 实战复盘

2026-10-14 · AI 技能包

这周给本地博客工作流装了一个新东西：web-design-skill-matrix（v0.6.0）。本来只是想"装个技能包"，结果一装就牵出 77 项关联依赖——从 6 项可用补齐到 35 项，剩下 42 项没有来源。整个过程走完，最大的收获不是技能变多了，而是"怎么诚实地知道自己会什么、不会什么"。

一、安装之后，先面对 77 项关联技能

技能矩阵安装后会自动扫描关联技能清单。第一轮扫描结果很直接：77 项关联技能里只有 6 项在本机就绪，其余大面积缺失。

二、42 项"无来源"：清单是诚实的边界

补依赖的时候，最怕的不是缺，而是"看起来有"。29 项有明确来源的技能很快就补齐了；剩下 42 项在公共来源、技能仓库、路由表里都查不到出处。这时候的正确做法不是硬凑一个来源，而是把它们单独列成清单，标注"无来源、未验证"。

这 42 项既不影响已有技能运行，也不占路由。它们只是提醒我：技能矩阵的价值不是"什么都有"，而是"有什么、缺什么、不确定什么"一目了然。

三、路由校验 24/24：routing.json 是唯一真源

矩阵 v0.6.0 里，所有技能的调用入口都由 routing.json 定义。补齐依赖后跑了一遍路由校验：24 条路由全部通过，一条不多一条不少。

这条规则值得记住：routing.json 是唯一真源。技能再多，路由表里没有就不算数；路由表里写了，就必须能校验通过。先定真源、再谈数量，顺序不能反。

四、实战产出：首页、归档页、订阅就绪态

矩阵补齐不是终点，落地产出才算数。这周用它直接改了博客首页：新增暗色模式（CSS 变量 + localStorage 记忆 + prefers-color-scheme 默认）、订阅表单改为前端就绪态（不伪造后端地址）、导航加入归档入口，并新增 archive.html 归档页，同步更新 RSS 与 sitemap。

整个站点保持零外部依赖：无 CDN、无字体库、无第三方脚本，对比度满足 WCAG AA，并尊重 prefers-reduced-motion。

五、可复现步骤

  1. 安装 web-design-skill-matrix（v0.6.0），查看关联技能清单与就绪状态
  2. 对 77 项依赖做三类归档：已就绪 / 可补齐 / 无来源
  3. 按 routing.json 补齐 29 项可验证依赖，重新扫描确认 present=35
  4. 42 项无来源技能单独列清单，标注"未验证"，不写入路由
  5. 执行路由校验，确认 24/24 通过
  6. 用矩阵产出/升级页面，保持零外部依赖与 AA 对比度

六、v0.6.0 升级：第 7 个实战判例与版本自洽

复盘之后矩阵升到 v0.6.0，核心变化是新增第 7 个实战判例 C-007 深色霓虹玻璃拟态视觉模板（cases/dark-neon-glass-nav/，Next.js Pages Router + Tailwind 就绪）：#030523 深海军蓝画布 + 紫/青径向光晕 + 模糊光球动画（blur 静态滤镜、只动 transform、16~22s 错峰、prefers-reduced-motion 降级）+ 玻璃拟态吸顶导航（backdrop-filter + 滚动加深），case.md 含「框架迁移三步」与可复用令牌表。

同时 references/design-tokens.md 深色轨补「深海军蓝 + 紫/青」变体指针，并同批校齐版本漂移：frontmatter/H1/README 由 0.4.0 对齐至 0.6.0，README 子模块数、优先级串、用例数等陈旧表述一并修正。路由规则与验证逻辑未改动，verify_route.py 仍 24/24——和复盘时一样，真源不变，数量再涨也不乱。

七、v0.6.2 升级：C-008 按手机端四项修改重构

C-008 浅色 RGB 幻彩霓虹模板（cases/light-rgb-neon/，单文件 index.html、零外部依赖不引 CDN）上线后，基于手机端实际浏览截图做了四项修改，升到 v0.6.2（判例内部 v1.0.0 → v2.0.0）：

  • ① 默认明亮：页面默认即浅色明亮，不依赖主题切换或系统偏好——html/body 双写 background: var(--page)（#F6F7FB）并显式 color-scheme: light 锁定，彻底移除任何渲染成深色的因素。
  • ② 7 段多彩：红绿蓝三原色扩展为 红 → 橙 → 黄 → 绿 → 青 → 蓝 → 紫 7 段，统一 --grad-7 渐变语言（92deg 连续过渡）贯穿光晕（4 块中间色径向渐变）、Hero 渐变标题、主按钮、图标、卡片高光线、柱状图与指标数字，视觉上显著更"幻彩"。
  • ③ 跑马灯修复强化为 7 段：弃用兼容性差的 mask-composite: intersect，改用 @property --angle 注册 CSS 自定义属性 + conic-gradient(from var(--angle)) 让浏览器直接插值角度，实现沿卡片边缘顺时针匀速流动的 7 段连续渐变描边；iOS Safari 16.4+ 原生平滑，旧版自动降级为静态 7 段多彩描边（不依赖 mask 也能看到完整幻彩边框）；WebKit 侧保留 -webkit-mask-composite: xor 挖心。多张卡片各自独立：每卡一个 .rgb-marquee 环 + CSS 变量 --marquee-duration / --marquee-direction 控制时长与方向；prefers-reduced-motion 下停转。
  • ④ 375px 竖屏优先：移动端为主要设计考量——汉堡菜单、按钮触控区 ≥44px、栅格逐级降级、字体与间距按小屏收紧；性能上移动端取消卡片 backdrop-filter、导航 blur 降至 10px（大 blur 层 5+ → 1），降低低端机负担，桌面端在此基础上增强。

跑马灯核心复用要点：多卡独立（每卡一条 @keyframes 旋转 --angle，时长/方向用 CSS 变量批量复刻）；性能与无障碍（@property 插值只更新已注册属性，不进重排重绘；reduced-motion 停转降级静态描边）；可迁移性（自定义类集中在一个 <style> 块内，复制整块即可搬到任意页面）。

同批更新的还有 references/design-tokens.md 浅色轨变体（三原色 → 7 段幻彩）、README/SKILL 版本与判例描述（v0.6.2）、case.md 对齐新实现；路由规则与验证逻辑仍未改动，verify_route.py 继续 24/24。

八、v0.6.3 升级：修复跑马灯目视不可见

上线后收到真实反馈：卡片边缘跑马灯在手机上目视不可见。v2 的实现是 padding:2px 细描边 + 挖心后的细环带，手机小屏上几乎无感。v0.6.3（判例内部 v2.0.0 → v2.1.0）唯一改动焦点就是跑马灯可及性：

  • ① 光柱加粗 10px：新增 --marquee-width: 10px 默认变量统一控制光柱厚度（padding: var(--marquee-width) 单处改值全卡生效），是卡片视觉边框 1px 的 10 倍（> 3 倍要求），375px 手机视口下肉眼清晰可见。
  • ② 提饱和：7 段跑马灯色值整体提饱和（红 #FF1E56 / 橙 #FF6D00 / 黄 #FFEA00 / 绿 #00FF7A / 青 #00E5D8 / 蓝 #00B8FF / 紫 #A944FF），浅底上对比更鲜明。
  • ③ 霓虹发光：实测发现 Chrome 中 filter + mask + conic 组合不渲染 drop-shadow，改由 .rgb-card 自身 box-shadow 红蓝双层外发光（16px / 30px 渐晕，hover 增强），像素级确认光柱外侧红蓝霓虹色带。
  • ④ 流速 3s/圈：4.2s → 3s（2–4s 舒适区间）。
  • ⑤ 兼容性：@supports not (background: conic-gradient(...)) 显式检测，极旧浏览器退为同宽纯色粗环（同样 10px）；无 @property 环境静态 7 段粗彩环同样加粗；reduced-motion 停转但光柱保留。

实测留证：375×812 移动视口连拍截图（marquee_t0.png / marquee_t1.png）三项验证全部通过——① 粗渐变光带目视可见；② 光带外侧红蓝霓虹光晕生效；③ 两张连拍四角色块互换，证明光带顺时针流动。

同批同步版本号全链路：<title> / Hero 徽章 / Footer / 头部注释 / case.md / README / SKILL / design-tokens 统一 v2.1.0 / v0.6.3；路由规则与验证逻辑仍未改动，verify_route.py 继续 24/24。

九、模板预览说明（商业资产保护）

web-design-skill-matrix 将作为付费专家技能出售，C-008 浅色 RGB 幻彩霓虹模板与 C-009 暗色系 RGB 幻彩霓虹模板的实现细节（单文件源码、@property 跑马灯实现、7 段色值体系）属于商业资产，公开演示页与文章预览链接已撤下，不再以 iframe 或在线链接形式展示。付费用户将通过交付包获得完整模板、判例文档与迁移指南。此处仅保留文字化描述：

  • 浅色版 C-008：明亮浅色画布 #F6F7FB + 7 段红橙黄绿青蓝紫霓虹光晕与渐变标题/按钮/卡片高光 + 卡片边缘 5px 光柱顺时针跑马灯（3s/圈、红蓝霓虹外发光）。
  • 暗色版 C-009：近黑画布 #05060F + 同款 7 段 RGB 幻彩语言 + 同款 5px 跑马灯，与浅色版构成明暗双生模板族，明暗双轨光柱宽度统一。

十、v0.6.4 升级：跑马灯光柱减半 + 暗色系 RGB 判例 C-009

本轮升级两个焦点：

  • ① 跑马灯光柱 10px → 5px 全局减半（C-008 判例内部 v2.1.0 → v2.2.0）：--marquee-width 由 10px 统一改为 5px——padding:var(--marquee-width) 单变量全卡生效，fallback 静态 7 段彩环与 @supports 纯色兜底同步减半，明暗双轨（C-008 浅色 / C-009 暗色）统一为 5px。375px 实测 5px 光柱在浅色与近黑底上均清晰可见、顺时针流动、红蓝光晕生效，观感更克制，适配付费专家模板定位。
  • ② 新增暗色系 RGB 幻彩霓虹判例 C-009（cases/dark-rgb-neon/，自包含单文件 index.html + case.md）：暗色底采用近黑 #05060F（比 C-007 #030523 更近黑，RGB 光晕对比更强）+ 与 C-008 完全同款的 7 段 RGB 幻彩语言（--grad-7 / --ring-7 色值一致）+ 同款 5px 跑马灯（@property --angle + conic-gradient(from var(--angle)) 顺时针流动、多卡独立 --marquee-duration/--marquee-direction 变量 + 负延迟错峰、prefers-reduced-motion 停转降级、@supports 纯色兜底）+ 玻璃拟态吸顶导航（移动端 blur 10px / 桌面 20px）+ 375px 竖屏优先（汉堡菜单、触控区 ≥44px、栅格逐级降级、移动端取消卡片 backdrop-filter）。

元数据同步：references/design-tokens.md 浅色轨变体更新 5px 说明并新增暗色轨「RGB 7 段幻彩」变体；README / SKILL 升 v0.6.4（cases 索引 8→9）；changelog 记录 v0.6.4 与 C-008 内部 v2.2.0。路由规则与验证逻辑未改动，verify_route.py 仍 24/24。

这次复盘的结论只有一句：工具矩阵最大的价值，是让你对"自己会什么"有一个不撒谎的清单。35 项验证过的、42 项存疑的，都摆在那里，比"感觉什么都会"有用得多。
