运费从不按你称的重量收：体积重审计与包装改造的回本期

2026-11-08 · 商业操盘

SKU-B 的实重是 0.90 公斤，计费重 12.50 公斤，单件运费 92.75 元——售价 299 元的 31.0%。它一个月出 1,460 件，吃掉 135,415 元，占整个仓运费的 40.7%，而报表上它只是一只轻飘飘的毛绒靠垫。本文用 6 个 SKU、8,740 单、月 GMV 1,762,460 元的算例，把体积重、0.5 公斤取整、首重续重与渠道抛比拆成可执行口径：按实重做的运费预算低估 117,130 元，偏差 54.39%；把 B 的箱规压到 50×50×12、再按货物密度分派三条渠道，月运费从 332,495 元压到 236,060 元，省下 96,435 元，等于 6% 净利率下净利的 91.2%。附零依赖脚本，输出与表格逐格对得上。

一、按实重做的运费预算，为什么会系统性偏乐观

第一层误判是不上秤。产品净重 0.62 公斤的靠垫，包装后上秤 0.90 公斤，差 45%，这一层还能靠称补救；真正的问题是这个 0.90 公斤渠道根本不用——它用的是体积重。用净重、用毛重、用“大概一公斤”，三种做法在轻泡货上会得到三个都错的答案，而且都偏乐观。

第二层误判是把抛比当行业常数。同一只 50×50×30 的箱子，抛比取 6000 算出体积重 12.50 公斤，取 8000 只算 9.38 公斤，计费重 12.5 对 9.5，一票差 17.25 元。抛比写在哪张合同上、旺季会不会被临时收紧，不先去问清楚，运费模型就是猜的。

第三层误判是把 0.5 公斤取整当零头。六个 SKU 全仓一个月，被取整吃掉的部分是 9,321 元，年化 111,852 元。这个数字不算大，可它是白付的：换不回任何交付、任何时效、任何客诉减少。

二、体积重与计费重的四步算法

口径是四步，缺一步就错，且四步的错误方向全部指向“低估”。第一步量外箱最大长宽高，不是产品尺寸，也不是内托尺寸；第二步算体积重；第三步取实重与体积重的较大值，再向上取整到渠道步长；第四步套首重续重。

体积重(kg) = 长(cm) × 宽(cm) × 高(cm) ÷ 抛比
计费重(kg) = ceil( max(实重, 体积重) ÷ 步长 ) × 步长      # 步长常见 0.5kg 或 1kg
运费(元)   = 首重费 + max(0, 计费重 − 首重kg) × 续重费

抛比换成密度更好记：6000 意味着每立方米按 166.7 公斤收费，5000 按 200 公斤，8000 按 125 公斤。渠道给你 8000，等于默许你的轻泡货按更低的等效密度过账；给你 5000，等于每立方米多收 33 公斤的钱。同一个箱子换一条渠道，运费能从 92.75 元变成 98.50 元，跟包装一点关系都没有。

取整只进不退，加上首重门槛，会把低单价轻小件的运费率顶到荒唐的位置：SKU-E 实重 0.45 公斤、体积重 0.88 公斤，计费重 1.0 公斤，18 元首重照付，占 79 元售价的 22.8%。它的病灶不是抛重，是首重。

四、判定用三条阈值，不用一条

阈值一，体积重 ÷ 实重 ≥ 2.0，判抛货。B 是 13.89，E 是 1.94，A 是 1.43，C、D、F 都在 1 以下。这条线管的是“包材有没有救”。

阈值二，单件运费 ÷ 售价 ≥ 20%，判运费击穿。C 的抛比只有 0.29，按第一条判它是实重货，一票通过；但它的 31.00 元运费占 99 元售价的 31.3%，比 B 还高一点。这类问题改箱规无效，要改定价或包邮门槛。

阈值三，计费重 − 实重 ≥ 1.0 公斤，判处置优先级。B 差 11.60 公斤，改一次箱规省一半运费；C 差 0.40 公斤，那 0.40 公斤全是 0.5 取整与首重造成的地板，改包材白花钱。

五、包装改造：先看实重有没有托底

B 的箱规从 50×50×30 压到 50×50×12，体积重 12.50 降到 5.00 公斤，计费重 12.5 降到 5.0，单件运费 92.75 降到 44.00 元，降幅 52.6%，月省 71,175 元。真空压缩袋 1.2 元/件、月耗材成本 1,752 元，加一次性 8,000 元，回本期 3.4 天。

A 的箱规从 60×40×15 压到 60×40×10，体积重 6.00 降到 4.00 公斤，但实重 4.20 公斤托底，计费重只从 6.0 降到 4.5，单件运费 50.50 降到 40.75 元，省 9.75 元、月省 7,995 元；内托改模一次性 12,000 元，回本期 45 天。

同样是压箱规，一个 3.4 天回本，一个 45 天回本——差别不在包材工艺，在实重有没有托底。A 的收益天花板由 4.20 公斤锁死，把体积压到 4.00 公斤以下一分钱也不再多省。改造前先算这一步，能省掉一整轮无效打样。

六、渠道：抛比不是越松越好

三条渠道摆在一起看，最容易踩的坑是只看续重。CH-B 的续重 5.0 元是全仓最低，但抛比收紧到 5000，全量跑下来 341,950 元，比 CH-A 还贵 9,455 元——抛比收紧一档，续重省下来的钱全吐回去还不够。

CH-C 抛比 8000、首重 15 元、续重 9.0 元，全量 323,160 元。它对轻泡货有利（B 91.50 对 92.75、E 15.00 对 18.00），对重货不利（C 33.00 对 31.00、D 37.50 对 34.25）。没有一条渠道在所有 SKU 上都赢，所以“统一走最便宜那条”本身就是错的。

七、四个方案摆在一起，钱是谁挣的

只切渠道省 21,025 元（6.32%）；只改包装省 79,170 元（23.81%）；两件一起做省 96,435 元（29.00%）。包装改造贡献了 82.1%，渠道分派贡献 17.9%。渠道是谈来的，箱规是自己能定的——先做能定的那件。

八、脚本与月度落地口径

脚本只用标准库。输入列固定：sku、L_cm、W_cm、H_cm、weight_kg（上秤毛重）、divisor、first_fee、addl_fee、orders、price。实重口径那一列是故意留的对照——它就是大多数团队现在用的算法，跑出来的差值就是被抛重吃掉的利润。

# -*- coding: utf-8 -*-
"""计费重量审计：体积重 / 抛货 / 运费偏差（零依赖）"""
import csv
import math
import sys

STEP = 0.5          # 计费重取整步长（kg），按渠道合同
ALERT_RATIO = 2.0   # 体积重 / 实重 超过 2 倍即判抛货


def load(path):
    with open(path, encoding="utf-8") as f:
        return [dict(r) for r in csv.DictReader(f)]


def dim_weight(L, W, H, divisor):
    return L * W * H / divisor


def billable(weight, vol_weight):
    base = max(weight, vol_weight)
    return math.ceil(base / STEP) * STEP


def freight(bill, first_kg, first_fee, addl_fee):
    return first_fee + max(0.0, bill - first_kg) * addl_fee


def audit(rows):
    out = []
    for r in rows:
        L, W, H = float(r["L_cm"]), float(r["W_cm"]), float(r["H_cm"])
        w = float(r["weight_kg"])
        dv = float(r["divisor"])
        vol = dim_weight(L, W, H, dv)
        bill = billable(w, vol)
        weight_only = billable(w, 0.0)                  # 只按实重的错误口径
        fee = freight(bill, 1.0, float(r["first_fee"]), float(r["addl_fee"]))
        fee_w = freight(weight_only, 1.0, float(r["first_fee"]), float(r["addl_fee"]))
        n = int(r["orders"])
        price = float(r["price"])
        out.append({
            "sku": r["sku"], "vol": vol, "bill": bill, "weight_only": weight_only,
            "ratio": vol / w, "fee": fee, "fee_w": fee_w, "orders": n,
            "month": fee * n, "gap": (fee - fee_w) * n,
            "share": fee / price, "alert": vol / w >= ALERT_RATIO,
        })
    return out


def report(rows):
    gmv = sum(float(r["price"]) * int(r["orders"]) for r in rows)
    head = "%-6s %7s %7s %7s %7s %7s %8s %7s %6s  %s"
    print(head % ("SKU", "体积重", "计费重", "实重口径", "单件费", "体积占比",
                  "月运费", "费用/价", "抛比", "判定"))
    total = gap = 0.0
    for r in audit(rows):
        total += r["month"]
        gap += r["gap"]
        print(head % (r["sku"], "%.2f" % r["vol"], "%.1f" % r["bill"],
                      "%.1f" % r["weight_only"], "%.2f" % r["fee"],
                      "%.2f" % r["ratio"], "%.0f" % r["month"],
                      "%.1f%%" % (r["share"] * 100), "%.2f" % r["ratio"],
                      "抛货" if r["alert"] else "实重"))
    print("合计 月运费 %.0f 元 占 GMV %.2f%%  实重口径低估 %.0f 元（%.2f%%）"
          % (total, total / gmv * 100, gap, gap / (total - gap) * 100))


if __name__ == "__main__":
    report(load(sys.argv[1] if len(sys.argv) > 1 else "sku.csv"))

跑法：python3 dim_weight_audit.py sku.csv。用本文 6 行数据跑，输出与表 1 逐格对得上：合计月运费 332,495 元、占 GMV 18.87%、实重口径低估 117,130 元（54.39%）。换渠道只要改 divisor、first_fee、addl_fee 三列，脚本一个字不用动。

月度节奏三件事：每月 3 日拉上月上秤毛重与外箱最大尺寸（不是产品规格书上的数字）；4 日出抛比、运费率、判定三张表；6 日处置——抛货改箱规、运费率击穿的改定价或包邮门槛、两样都不改的写进选品淘汰名单。把字段和阈值写进技能包的 front matter，AI 每月只做取数、算重、出清单；人只做两件：签包材改动单、带着计费重分布去找渠道谈抛比。

九、结语：运费在你画刀模那天就定了

《孙子兵法·作战篇》讲“国之贫于师者远输，远输则百姓贫”。两千五百年前说的是粮道，今天说的是箱规与抛比。运费不是财务科目，是产品结构的一部分——它的高低在画包装刀模那一刻就定了，只是账单晚一个月才到。晚看一步，就是一个月 11.7 万元的差额。
