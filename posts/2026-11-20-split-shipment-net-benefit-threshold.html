多仓拆单别只看费率表：跨境尾程拆单的净收益阈值

2026-11-20 · 商业操盘

拆单发货这个动作，多数团队是凭直觉做的：近仓有货的部分就近发，远仓的另发一个包裹，看起来只赚不亏。把六类订单的账摊开，结论是反的——拆单省下的是近区那一段的费率差，0.79 到 26.10 元；多付的是一个新包裹的首重 26.00 到 30.50 元，再加操作费 8.50 元，两边量级差近 20 倍。六类里五类净亏 10.71 到 31.48 元，只有客单价 1,860 元、近仓可发 11.60 kg 的 5-SKU 套件单净赚 16.34 元，占订单 3.33%。这条策略一年只值运费的 0.87%（121,555 元）；无差别全拆则一年多付 5,221,402 元、运费的 37.23%。而它真正的价值不在省钱，在于把“拆不拆”从会议争论变成一行阈值判断。

一、拆单不是运费题：省下的费率差与多付的首重，量级差 20 倍

先承认一个事实：尾程费率表是分段线性的，每个 zone 只有两个参数——一个包裹的首重 base，和每公斤的续重单价 rate。拆单这件事，在费率表上被切的只有两块：近区那部分的 rate 更便宜，这里省；远区那部分照旧，不省。但拆单同时也把“包裹数”从 1 变成 2，第二个包裹的 base 是躲不掉的固定收费，再加上拣货、包装、面单、复核的操作费。

两边的量级差从第一个算例就能看清。O1 是一张 2-SKU 轻件单，总重 0.90 kg，其中 0.35 kg 在近仓（zone 2）能发，其余 0.55 kg 只能在远仓（zone 8）。跨区费率差 2.25 元每公斤，0.35 kg 省下 0.79 元；第二个包裹要付 base 26.00 元加操作费 8.50 元。省 0.79 元、付 34.50 元，这笔账在任何重量下都不会自己翻过来——除了重量足够大，让那 2.25 元的费率差累积到 34.50 元以上。

二、三段成本模型：分区费率、拆单固定成本、时效收益

第一段是分区费率。表 1 是八分区的地面费率：首重从 zone 1 的 24.00 元爬到 zone 8 的 39.50 元，续重从 3.60 元每公斤爬到 6.10 元。注意两个涨幅不同——base 涨 64.6%，rate 涨 69.4%，但 base 是绝对值 15.50 元的差，rate 只有 2.50 元每公斤。这就是为什么轻件拆单必亏、重件才有戏：轻件付的是 base 的绝对值差，重件赚的是 rate 的单价差。

三、闭式阈值：临界近仓重量 w* 决定一切

第二段是拆单固定成本。一个额外包裹的实付账拆四块：拣货与二次复核 3.20 元、包装耗材 1.40 元、面单与打单 1.20 元、WMS 与人工处理 2.70 元，合计 8.50 元。第三段是时效收益：整单跨区发货的实测退款率 4.6%、差评率 5.4%；拆单后只有子包裹延迟，退款率 2.9%、差评率 3.1%。差 1.7 个百分点按 30% 的退货货损折算 0.51%，差评差 2.3 个百分点、每条折算 0.36 个客单价的后续转化折损，折算 0.83%，合计 1.33% 客单价。

三段合起来，拆单相对整单远发的净差额只有一个式子：净差额 = 近区首重 + 操作费 − 近仓可发重量 × 跨区费率差 − 1.33% × 客单价。令它为零，得到临界近仓重量 w* = (近区首重 + 操作费 − 1.33% × 客单价) ÷ 跨区费率差。

这个式子只有四个输入，而且三个是合同参数：首重、费率差、操作费都写在承运商与仓配合同里，一年谈一次。唯一能每天变的是客单价。所以 w* 的含义很硬：近仓至少要能发走这么多公斤，拆单才开始付得起；发不到，拆单就是给承运商多交一次首重。

六类的结论几乎没有悬念：五类净亏，金额从 10.71 元（O6 礼盒单）到 31.48 元（O1 轻件单）。亏损的排序不是按重量排的，是按 w* 与实发重量的比值排的：O1 的 w* 是 14.34 kg，实际只能发 0.35 kg，差 41 倍，亏得最狠；O6 的 w* 是 9.63 kg，实际 3.90 kg，差 2.5 倍，亏得最轻。

唯一过线的是 O5：14.20 kg 的套件单，近仓能发 11.60 kg，w* 只有 4.34 kg，净省 16.34 元。它占月单量 3.33%。这个占比不是巧合——套件单的重量集中在近仓可发的部分，且客单价 1,860 元把时效收益推到 24.74 元，两者同时成立，阈值才被突破。

五、拆单的收益不在运费里：O5 的 26.10 对 26.00

把 O5 的账单独拆开，会看到一件容易被忽略的事。这单拆单省的费率差是 11.60 × 2.25 = 26.10 元；多付的近区首重是 26.00 元；两个数字几乎相等，运费层面拆单只省了 0.10 元。再把 8.50 元操作费算进去，运费这一层是净多付 8.40 元。整单最终净省 16.34 元，全部来自 24.74 元的时效收益。

这条结论会改变谈判对象。如果拆单的收益来自运费，团队该去找承运商谈费率；既然收益来自时效，该谈的是仓网与客单价结构。同一个逻辑也解释了为什么 O6（客单价 1,240 元、近区首重 26.00 元）差 10.71 元没过线：它的时效收益 16.49 元已经不小，但省下的费率差只有 7.29 元，抵不上 36.70 元的多付。

这张表最值得看的是“无论怎么压都一样”。操作费从 12.00 砍到 3.00 元、降幅 75%，O1 的亏损从 34.98 元收窄到 25.98 元，仍然亏 25.98 元；O6 从 14.21 元收窄到 5.21 元，仍然亏。判定一次都没变。

原因在 break-even 操作费上：使净差额为零的操作费上限，O1 是 −22.98 元、O2 是 −19.79 元、O3 是 −10.52 元、O4 是 −6.74 元、O6 是 −2.22 元，全是负数。只有 O5 的 break-even 是 +24.84 元。负数意味着操作费要收到负数——即仓配方倒贴钱——才可能翻盘。真正压住这五类的不是操作费，是第二个包裹 26 到 30.50 元的首重。

跨区溢价是唯一能真正撬动判定的外部变量。p 从 15% 抬到 60%，年节省从 6,339 元涨到 248,359 元，涨了 39 倍；O5 的净收益从 0.85 元涨到 32.69 元；O4 在 p = 60% 时才第一次过线，净省 0.20 元——几乎贴着零。

问题是这个变量买不来。八分区地面费率里，zone 8 对 zone 2 的 rate 溢价是 58.4%，这已经接近多数承运商合同区间的上沿；要求 60% 的统一折扣意味着近区费率被压到远区的四成，谈判上等于让对方单独给近区开一条底价线。等这个条件成立，不如改仓网——把近仓可发比重提上去，w* 的门槛可以直接失效。

月 18,600 单的基线运费是 1,168,786 元，年化 14,025,437 元。阈值策略一年省 121,555 元，占运费 0.87%；全拆一年多付 5,221,402 元，占运费 37.23%。三个数字放在一起，结论很清楚：拆单规则不是战略，是运费表上的第四位小数。但它也不是零——12 万级的年省，够付一个人的绩效，而它只需要一条写进 WMS 的分单判断。

要提醒一句口径风险：这 0.87% 依赖 1.33% 的时效折算率。如果实际差评与退款的差额只有 0.7%，O5 的净收益会从 16.34 元掉到 4.9 元附近，年省跟着缩到 3 万级；如果差额到 2.2%，O6 也会过线，年省抬到 20 万级。所以 1.33% 这个参数必须用自己的退款与差评工单实测，不能抄别人的。

九、执行清单与结语：不可胜在己，拆单只是脚注

季度动作四步。第一，把承运商费率表换算成每 zone 的 base 与 rate 两参数，重算每个订单类的 w*，写成一张表交给 WMS。第二，分单规则只在近仓可发重量大于 w* 时触发拆单，其余走整单远发或补货等待——把“能不能拆”变成“该不该拆”。第三，把 1.33% 这个时效折算率接到月度退款与差评工单上，它一变，w* 就变。第四，也是最值钱的一步：盯住近仓可发比重，这个比重从 0.35 提到 0.90，w* 的门槛直接失效，比谈任何费率都快。

《孙子·军形》讲“昔之善战者，先为不可胜，以待敌之可胜”。拆单是“待敌之可胜”——等费率差、等客单价、等跨区溢价凑齐条件，能赢的订单只有 3.33%。“不可胜在己”的那一半是备齐率：仓网布局与库存前置，让近仓能发走的那部分重量自己长起来。拆单规则是这一题的脚注，不是正文；把脚注当正文写，就是 O1 那笔一年亏 31.48 元乘 6,200 单的账。

附：可复现脚本（Python 3，仅标准库）

下面这段跑出表 3 到表 6 的全部数字，不依赖任何第三方包。换自己的数据只改 ZONES 与 ORDERS 两处；w* 的公式与正文第三节逐字对应。

# split_ship.py -- multi-warehouse split-shipment break-even (standard library only)
ZONES = {1: (24.0, 3.60), 2: (26.0, 3.85), 3: (28.2, 4.15), 4: (30.5, 4.60),
         5: (32.8, 4.95), 6: (35.0, 5.35), 7: (37.2, 5.72), 8: (39.5, 6.10)}
F_OP = 8.5          # picking + packaging + label per extra parcel
TIME_RATE = 0.0133  # service-downtime recovery as a share of order value

def freight(z, w):
    base, rate = ZONES[z]
    return base + rate * w

# name, far zone, near zone, total kg, near-shippable kg, order value, orders/month
ORDERS = [
    ("O1 2-SKU light",   8, 2,  0.90,  0.35,  168, 6200),
    ("O2 3-SKU mid",     7, 3,  3.20,  1.80,  420, 4900),
    ("O3 4-SKU bulki",   6, 2,  6.50,  4.20,  690, 3400),
    ("O4 5-SKU heavy",   8, 4,  9.80,  7.15,  980, 2100),
    ("O5 5-SKU suite",   8, 2, 14.20, 11.60, 1860,  620),
    ("O6 3-SKU gift",    7, 2,  5.40,  3.90, 1240, 1380),
]

def solve(f_op=F_OP, p=None):
    rows, base, best, allsplit = [], 0.0, 0.0, 0.0
    for name, zf, zn, W, wb, V, q in ORDERS:
        single = freight(zf, W)
        if p is not None:                      # near rate discounted off the far rate
            near = ZONES[zn][0] + ZONES[zf][1] * (1 - p) * wb
            gap = ZONES[zf][1] * p
        else:
            near = freight(zn, wb)
            gap = ZONES[zf][1] - ZONES[zn][1]
        split = near + freight(zf, W - wb) + f_op
        T = TIME_RATE * V
        net = split - T - single
        w_star = (ZONES[zn][0] + f_op - T) / gap
        rows.append((name, single, split, T, net, w_star, "SPLIT" if net < 0 else "ONE"))
        base += q * single
        best += q * min(net, 0.0)
        allsplit += q * net
    return rows, base, best, allsplit

rows, base, best, allsplit = solve()
for r in rows:
    print("%-18s single=%7.2f split=%7.2f T=%6.2f net=%+8.2f w*=%7.2f %s" % r)
print("freight baseline %.0f/month  saving %.0f/yr (%.2f%%)  split-all %+.0f/yr (%.2f%%)"
      % (base, -best * 12, -best * 12 / (base * 12) * 100, allsplit * 12, allsplit * 12 / (base * 12) * 100))
print("split share %.2f%%" % (sum(q for (_, _, _, _, _, _, q), r in zip(ORDERS, rows)
                                if r[6] == "SPLIT") / sum(o[6] for o in ORDERS) * 100))
for f in (3.0, 6.0, 8.5, 12.0):
    rs, _, _, _ = solve(f_op=f)
    print("F=%4.1f " % f + " ".join("%s:%+7.2f" % (r[0][:2], r[4]) for r in rs))
for p in (0.15, 0.30, 0.45, 0.60):
    rs, _, best_p, _ = solve(p=p)
    print("p=%.0f%% " % (p * 100) + " ".join("%s:%+7.2f" % (r[0][:2], r[4]) for r in rs) +
          "  saving/yr=%+.0f" % (-best_p * 12))

输出要点：六类净差额 +31.48、+28.29、+19.02、+15.24、−16.34、+10.71 元；w* 14.34 到 4.34 kg；月运费基线 1,168,786 元、年省 121,555 元（0.87%）、全拆多付 5,221,402 元（+37.23%）；拆单占订单 3.33%。逐格与表 3 到表 6 对得上。
