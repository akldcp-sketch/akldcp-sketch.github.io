SKU 动销分层：先分层再砍货的尾部治理口径

2026-11-02 · AI 技能包 · 商业操盘

库存是已经花掉的现金，货架上的每一件都对应一张已经付过的发票。SKU 动销分层和砍货经常被当成同一件事，其实是两个口径：分层决定流量和补货往哪放，砍货决定现金从哪收回来。口径混用的后果很具体——正在爬坡的新品被当滞销清掉，动销慢却压着大额库存的老货反而留着。本文用 30 个在售 SKU 的月度数据，把两个口径拆开算一遍。

一、SKU 动销分层与砍货是两件事：三个口径错位

第一个错位是拿销售额占比直接定生死。帕累托分层回答的是“资源该往哪投”，不是“哪款该下架”。按累计销售额划线，低单价、高出货的款会被划进 C 层，它的周转并不慢，砍掉只会白丢毛利。

第二个错位是只看销量不看库存。月销 8 件和月销 800 件的两个 SKU，如果前者压了 700 件、后者只有 200 件，占款上完全不是一回事。销量是流量指标，占款才是现金指标，淘汰必须用现金指标。

第三个错位是不设观察期。本月零销量的 SKU 可能 20 天前才上架，直接进淘汰池，等于用上架时间惩罚新品。这条错位在每个旺季前都会重演一次。

二、SKU 动销分层：累计销售额 70 / 90 / 99 三条线

口径先定死：观察窗 30 天，销售额＝售价 × 30 天销量，占款＝库存件数 × 单位成本，按销售额降序累计划线。A 层到累计 70%，B 层 70%—90%，C 层 90%—99%，D 层 99% 以上或 30 天零销量。层均周转＝该层 30 天销量 ÷ 该层库存件数。

A 层 5 个 SKU，占宽度 16.7%，吃掉 71.2% 销售额，层均月周转 0.74 次，折合库存 40 天卖完。D 层 12 个 SKU 只出 0.9% 销售额，层均月周转 0.03 次，折合 1000 天。C 层加 D 层共 20 个 SKU、占宽度 66.7%，销售贡献 9.1%，却压着 23.0% 的占款。

这组数字的正确用法不是“砍 20 个”，而是两个动作：A 层保供、不断货、优先配流量；C 层停止补货，让库存自然出清。分层只负责分配资源，别让它越权去决定生死。

三、砍货口径：周转 0.3 次 + 占款 3000 元双门槛

月周转次数＝30 天销量 ÷ 当前库存件数。门槛定 0.3 次，等于现有库存够卖 100 天以上；再叠加占款不低于 3000 元——占款太小的款即使周转慢，处理它耗掉的沟通和物流成本比收回的钱还多，不值得上会。两条同时满足才进候选池。

四、可复现代码：一张 CSV 进，分层表与处置清单出

只用标准库，不需要 pandas。输入列固定为 sku、cat、days_listed、sales_30d、stock_qty、unit_cost、price、role，role 用来标记配件引流或共用包装，没标记留空。

# sku_layer.py —— 动销分层 + 尾部处置（零依赖）
import csv, sys

def load(path):
    with open(path, encoding="utf-8") as f:
        return [{"sku": r["sku"], "cat": r["cat"], "days": int(r["days_listed"]),
                 "sales": int(r["sales_30d"]), "stock": int(r["stock_qty"]),
                 "cost": float(r["unit_cost"]), "price": float(r["price"]),
                 "role": r.get("role") or ""} for r in csv.DictReader(f)]

def layerize(rows):
    for r in rows:
        r["rev"] = r["sales"] * r["price"]          # 月销售额
        r["amt"] = r["stock"] * r["cost"]           # 库存占款
        r["turn"] = r["sales"] / r["stock"] if r["stock"] else 0.0
    total_rev = sum(r["rev"] for r in rows)
    rows.sort(key=lambda x: x["rev"], reverse=True)
    cum = 0.0
    for r in rows:
        prev = cum / total_rev if total_rev else 0
        cum += r["rev"]
        after = cum / total_rev if total_rev else 1
        if r["sales"] == 0:
            r["layer"] = "D"
        elif after <= 0.70 or prev < 0.70:
            r["layer"] = "A"
        elif after <= 0.90 or prev < 0.90:
            r["layer"] = "B"
        elif after <= 0.99 or prev < 0.99:
            r["layer"] = "C"
        else:
            r["layer"] = "D"
    return rows, total_rev

def report(rows, total_rev):
    total_amt = sum(r["amt"] for r in rows)
    for k in "ABCD":
        items = [r for r in rows if r["layer"] == k]
        rev = sum(i["rev"] for i in items)
        amt = sum(i["amt"] for i in items)
        turn = sum(i["turn"] for i in items) / len(items) if items else 0
        print("%s %2d 个  销售 %9.0f (%4.1f%%)  占款 %9.0f (%4.1f%%)  周转 %.2f"
              % (k, len(items), rev, 100 * rev / total_rev,
                 amt, 100 * amt / total_amt, turn))

def disposal(rows, turn_gate=0.30, amt_gate=3000):
    hit = [r for r in rows if r["turn"] < turn_gate and r["amt"] >= amt_gate]
    hit.sort(key=lambda x: x["amt"], reverse=True)
    kill = 0.0
    for r in hit:
        why = []
        if r["days"] < 90: why.append("培育期")
        if r["role"]: why.append(r["role"])
        if not why: kill += r["amt"]
        print("%-9s %-4s 占款 %7.0f 周转 %.2f  %s"
              % (r["sku"], r["cat"], r["amt"], r["turn"], "/".join(why) or "淘汰"))
    print("命中 %d 条，可执行释放占款 %.0f 元" % (len(hit), kill))

if __name__ == "__main__":
    rows, total_rev = layerize(load(sys.argv[1]))
    report(rows, total_rev)
    disposal(rows)

用本文的 30 行数据跑一遍，输出与前面的表格逐格对得上：总销售额 863,540 元、总占款 579,765 元、命中 17 条、可执行释放 54,515 元。换数据源只要列名不变，脚本一个字都不用改。

五、三个不能一刀切的尾部 SKU

  1. 新品培育期。上架不足 90 天的 SKU 不进淘汰池，只监控环比增速。SKU-D10 零销量但只上架 26 天，占款 7,560 元，砍掉等于放弃一个还没跑完的测试。
  2. 配件引流。SKU-D06、D07 月周转 0.05，单独看是死货，但它们撑起主款的连带率和客单价；砍掉配件，A 层主款的转化会跟着掉。
  3. 共用包装耗材。SKU-D01 与 A 层主力款共用内衬和纸箱，砍掉它，主力款的包材采购量下滑、单价上升，省下的占款会从别处漏回去。

豁免不是免死金牌，是给期限：培育期满 90 天复盘一次，配件与共用包装每季度复核一次，复核不过照样进池。没有期限的豁免，三个月后就会变成新的库存黑洞。

六、把 SKU 动销分层做成 AI 技能包

固定输入、固定口径、固定输出，三件事凑齐就能交给 AI 跑。技能包只做三件：读表、判层、出清单；人只做两件：核豁免理由、签淘汰单。边界写清楚，它才不会自作主张把培育期新品也砍了。

---
name: sku-turnover-layering
description: 按 30 天销量与库存占款做 SKU 动销分层，输出尾部处置清单与豁免标记
inputs:
  - inventory.csv  # sku, cat, days_listed, sales_30d, stock_qty, unit_cost, price, role
gates:
  layer: {A: 0.70, B: 0.90, C: 0.99}
  disposal: {turn_max: 0.30, amount_min: 3000}
  exempt: [days_listed < 90, role == accessory, role == shared_pack]
outputs:
  - layer_report.md      # 四层 SKU 数 / 销售占比 / 占款占比 / 层均周转
  - disposal_list.csv    # 按占款降序，含豁免原因
  - cash_release.md      # 本月可释放占款金额与执行人签字位
---
月度节奏：每月 3 日出数，5 日审豁免，10 日前清仓单落地。跑过三次以后，会上的争论会从“这个款我觉得还能救”变成“这 7 个款账上压了 5.45 万，谁签”。

技能包最容易塌的地方是“人话边界没写”。把门槛、豁免、输出格式写进 front matter，比在提示词里反复叮嘱可靠——它不靠记性，靠文件。

七、结语：把库存当已花掉的现金看

《管子》讲“仓廪实而知礼节”，仓里有货是底气；但压着不动的货不是底气，是账上的洞。SKU 动销分层的价值不在报表好看，而在于每月能把一笔具体金额的现金从货架上拿回来——这个月是 54,515 元，下个月取决于名单有没有真的执行掉。
