亚马逊广告 ACOS 分层管理：把每日调价做成 AI 技能包

2026-10-22 · AI 技能包

亚马逊广告后台每天给一堆数字：impressions、clicks、spend、sales、ACOS。运营最容易犯的错，是拿一个统一 ACOS 阈值去卡所有广告活动——结果利润款被砍过头掉量，冲量款却烧到亏钱。做跨境操盘这几年，我的结论是：ACOS 必须分层管理，先按毛利率给 SKU 分档，再让脚本每天巡检、只盯超阈的那几个。

一、ACOS 分层管理的第一道坎：ACOS 不是越低越好

ACOS = 广告花费 ÷ 广告销售额。它的盈亏平衡点不是 0，而是毛利率：当 ACOS 等于毛利率时，广告带来的每个订单赚到的毛利刚好被广告费吃光。用公开可验证的行业口径举例，亚马逊 SP（Sponsored Products）广告的行业平均 CPC 约 $0.5–$1.5、平均点击率约 0.4%–0.8%、平均转化率约 9%–12%（Jungle Scout / Tinuiti 等机构历年报告数据）。换算下来，一个 $20 的订单广告费通常在 $1.5–$5，对应 ACOS 8%–25%。问题是：同一条广告，毛利 40% 的 SKU 打到 30% 依然赚钱，毛利 20% 的 SKU 打到 15% 已经亏钱——"越低越好"是个伪命题，"低于毛利率"才是底线。

二、ACOS 分层管理怎么分：按毛利率定四档目标

把每个 ASIN 的毛利率算出来，再按经营目的分四档。目标 ACOS 不是拍脑袋，而是给盈亏平衡线留出缓冲：利润款留一半毛利给其它费用和利润，冲量款和清仓款可以更靠近盈亏平衡线：

分层经营目的毛利率盈亏平衡 ACOS目标 ACOS
冲量款冲类目排名、起量30%30%≤ 25%
利润款主力利润贡献40%40%≤ 20%
清仓款去库存、回款优先45%45%≤ 35%
防守款维护排名、拦截竞对35%35%≤ 30%

分层一旦固定，所有人对账用同一张表：新品先归冲量款，跑两周出数据再改档；滞销转清仓款；主力 SKU 永远在利润款。分层不是终身制，每季度按毛利率重算一次。

7 个 SKU 里 4 个超阈，其中 A002 是主力利润款——它的 ACOS 30% 低于毛利率 40%，表面"还有利润"，但已经吃掉一半毛利空间。脚本跑完，超阈清单与调价建议 1 秒出，人只处理这 4 行：

TIERS = {
    "冲量款": {"gross_margin": 0.30, "target_acos": 0.25},
    "利润款": {"gross_margin": 0.40, "target_acos": 0.20},
    "清仓款": {"gross_margin": 0.45, "target_acos": 0.35},
    "防守款": {"gross_margin": 0.35, "target_acos": 0.30},
}

def acos_check(spend, sales):
    return spend / sales if sales > 0 else float("inf")

def daily_report(rows):
    """rows: [(sku, tier, spend, sales), ...]"""
    out = []
    for sku, tier, spend, sales in rows:
        cfg = TIERS[tier]
        acos = acos_check(spend, sales)
        target = cfg["target_acos"]
        status = "OK" if acos <= target else "OVER"
        bid_tip = ""
        if status == "OVER":
            cut = min(0.50, round(0.10 * acos / target, 3))  # 超阈越多，降幅越大
            bid_tip = f"建议出价下调 {cut:.0%}"
        out.append({"sku": sku, "tier": tier, "spend": spend, "sales": sales,
                    "acos": round(acos, 4), "target": target, "status": status,
                    "bid_tip": bid_tip})
    return out

rows = [
    ("A001", "冲量款", 300, 1500),
    ("A002", "利润款", 120, 400),
    ("A003", "利润款", 80, 350),
    ("A004", "清仓款", 60, 300),
    ("A005", "防守款", 40, 120),
    ("A006", "冲量款", 220, 1100),
    ("A007", "清仓款", 90, 200),
]
for r in daily_report(rows):
    print(r)

每天早上一张表：正常 SKU 不动，超阈 SKU 按建议降幅改出价，连续三天超阈才砍预算。规则越简单，团队越不会乱操作。

四、把 ACOS 分层巡检做成 AI 技能包

调价动作不能只活在某个人的脑子里。把巡检逻辑封装成技能包：输入是广告报表，输出是超阈清单与调价建议，SKILL.md 写清楚每一步，零基础同事也能跑。

# 技能包：ACOS 分层巡检（acos-tier-review）
name: ACOS 分层巡检
description: 输入亚马逊广告周报（SKU、分层、花费、销售额），输出 ACOS 与目标对比、超阈清单与调价建议
inputs:
  - rows: [[sku, tier, spend, sales], ...]
  - tiers: 分层配置（默认四档：冲量款/利润款/清仓款/防守款）
outputs:
  - 每个 SKU 的 ACOS、状态（OK/OVER）与建议降幅
steps:
  1. 导出广告后台最近 7 天 SP 活动报告，按 ASIN 汇总花费与销售额
  2. 为每个 ASIN 打分层标签（冲量/利润/清仓/防守）
  3. 运行 daily_report 脚本生成巡检表
  4. 超阈 SKU 按 bid_tip 调整出价，次日复查；连续 3 天超阈再砍预算
  5. 每季度按最新毛利率重算分层与目标 ACOS

真实团队里，这个技能包每天早上 9 点自动跑一遍，把超阈清单发到群里；调价从"每周花一上午翻报表"变成"每天花 10 分钟处理 3–5 行"。关键不是脚本本身，是分层口径固定——四档目标写死在配置里，谁算都一样。

五、可复现步骤

  1. 导出亚马逊广告后台最近 7 天 SP 报告，按 ASIN 汇总花费与销售额
  2. 算出每个 ASIN 的毛利率，按经营目的分四档（冲量/利润/清仓/防守）
  3. 按毛利率设定每档目标 ACOS（利润款留一半毛利缓冲）
  4. 运行 daily_report 脚本生成巡检表，核对 ACOS 与状态
  5. 只处理超阈 SKU：按建议降幅调出价，连续 3 天超阈再砍预算
  6. 把配置与脚本封装成 SKILL.md 技能包，交给团队每天早上自动巡检

ACOS 不是越低越好，是"每档有每档的线"。把线画清楚、让脚本每天去盯，人只处理超阈的那几行——这就是 ACOS 分层管理，也是它值得做成 AI 技能包的原因。公式、脚本、模板都摆在这里，拿去用，明天早上就能少翻一小时报表。
